# bungkus-mcc — Design Language ("Daun Pisang")

Status: proposal, revision 5 (product-owner decisions of 2026-09-30
applied, including the painted green background and the mascot). This is the shared visual language for bungkus products;
bungkus-mcc and bungkus-cli adopt it together (§2.4). Every fixed-width
mockup in this file was generated by a script and width-checked cell by
cell (`scratchpad/mock/gen3.py` + `check.py` from the review rounds; they
move into `internal/tui/testdata/` when code starts).

## 1. The image

Nasi lemak, bungkus-style: coconut rice on a square of banana leaf, folded
into a pyramid, wrapped again in newspaper, rubber band around it. Open it:
sambal (red, oily), half an egg (yolk), cucumber, fried ikan bilis and
peanuts, the leaf's green underneath.

| Element             | In the UI                                                |
|---------------------|----------------------------------------------------------|
| Daun pisang (leaf)  | Focus, running, healthy. Green.                          |
| Sambal              | Failure. Red-orange, used sparingly.                     |
| Kuning telur (yolk) | Attention: the agent is waiting for you. Amber.          |
| Nasi (rice)         | Primary text: the terminal's own foreground.             |
| Surat khabar        | Secondary text, chrome. Newspaper gray.                  |
| Minyak sambal       | Brand accent (title, selection). The oil stain on paper. |
| Getah (rubber band) | The status/mode bar that holds the packet together.      |
| Bungkus             | Done. A finished session is "wrapped".                   |

Theme name: **Daun Pisang** (`daun-pisang-dark`, default) and
**Daun Pisang Pagi** (`daun-pisang-light`).

## 2. Palette

Rules:

1. **mcc paints its own background — a low-saturation green — but only
   when it can do so faithfully: at TrueColor.** (Owner decision; this
   reverses the earlier "never paint" rule *for mcc*.) The green is chosen
   for hours of viewing: never pure black, body text around 11:1 rather
   than a glaring ~20:1. At 256/16 colours and under `NO_COLOR`, painting
   would produce a different, muddier green on every terminal, so mcc then
   uses the terminal's own background and foreground with the fallback
   token set (§2.3). Config `background: "paint" | "terminal"`, default
   `paint`. The output-pane emulator's default bg/fg are the same painted
   colours, and it answers the agent's OSC 10/11 queries with them, so the
   agent's screen blends in and it picks its dark (or light) theme.
2. Cards and surfaces are never painted separately (only the one screen
   background); selection uses reverse video, which by definition contrasts.
3. **Every state is glyph + word + colour.** Colour is never the only carrier.
4. Colours are declared once per token as: painted truecolor hex (used only
   when painting), fallback truecolor hex (used at TrueColor when
   `background: "terminal"`), and an explicit 256 and 16 index for the
   downsampled profiles. The indices start from
   `x/ansi.Convert256/Convert16` output and are overridden only where the
   converter makes two roles collide (marked ★). A test asserts
   `ok/warn/err/accent` are pairwise distinct at 256 and at 16 in both
   themes, and `fg-muted ≠ info`.

WCAG formula: (L1 + 0.05)/(L2 + 0.05), sRGB relative luminance. AA text
4.5:1, AA large/bold and non-text 3:1.

vanishes on a black background.

### 2.3 Fallback ladder

Profile detection (`COLORTERM`, `TERM`, `NO_COLOR`, `CLICOLOR_FORCE`, tmux)
is Bubble Tea v2 + colorprofile's job (`tea.ColorProfileMsg`). mcc then
chooses:

| Profile     | `background: paint` (default)            | `background: terminal`       |
|-------------|------------------------------------------|------------------------------|
| TrueColor   | painted `bg` + `fg` + painted token set  | terminal bg/fg + fallback hex set |
| 256 / 16    | terminal bg/fg + declared indices        | same                         |
| `NO_COLOR`  | terminal bg/fg, no colour, glyph + word + border weight only | same |

At 16 colours and under `NO_COLOR` the UI must be fully usable: glyph +
word per state, focus by border weight + marker, selection by reverse video.

## 3. Typography and glyphs

A TUI does not choose the font. We choose code points.

- **Recommended fonts** (README, not enforced): any monospace font; a Nerd
  Font only if the user opts into the `nerd` icon set.
- **Three glyph sets**, `icons: "ascii" | "unicode" | "nerd"` (config or
  `--icons`). **Default `ascii`** (decided by the product owner): the font
  cannot be detected, and ASCII state glyphs are unambiguous in every
  terminal and width setting. `unicode` and `nerd` are opt-in. All glyphs
  are 1 cell. The mockups in this file show the ascii default.
- **Borders and separators are not part of the icon set.** Box-drawing
  borders, the `·` separator and the mascot's half-block sprite are used
  whenever the locale is UTF-8; only a non-UTF-8 locale (or
  `TERM=linux|dumb`) switches them to `+-|`, `|` and the 4-line ASCII
  mascot. So the default screen is box-drawing borders with ascii glyphs,
  exactly as mocked.
- **Width risk (real, Japan-based team):** `●○■◆▶` and the box-drawing set
  are East Asian *Ambiguous* width. Terminals set to "ambiguous = wide"
  (common with CJK locales in iTerm2/kitty) render them 2 cells while
  lipgloss/x/vt count 1, and columns shift. Mitigation: every state and
  marker glyph in the `unicode` set is *Narrow* (checked with
  `unicodedata.east_asian_width`), and the default set is ascii anyway;
  borders remain ambiguous, as do the `·` separator (U+00B7) and the
  mascot's half-blocks `▀ ▄ █` (U+2580/2584/2588) — every terminal we
  target draws them 1 cell in practice, and the mascot only ever appears
  in an empty state where a 2-cell misrender costs nothing (a non-UTF-8
  locale switches them to `+-|`, `|` and the ASCII mascot). A recorded stream test with CJK, emoji and `⏺ ⎿` (Claude's own
  output) asserts the emulator's column positions match wcwidth — see
  CODING_RULES.md.

| Meaning       | nerd (U+)      | unicode | ascii (default) | width class |
|---------------|----------------|---------|-----------------|-------------|
| running       | spinner        | braille `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` | `\|/-\` | N |
| your turn     | U+F0E7 (bolt)  | `»`     | `~`   | N |
| needs you     | U+F071 (warn)  | `!`     | `!`   | Na |
| failed        | U+F00D (times) | `✗`     | `x`   | N |
| wrapped       | U+F00C (check) | `✓`     | `+`   | N |
| stopped       | U+F04D (stop)  | `▪`     | `#`   | N |
| subagent      | U+F0DA (caret) | `◦`     | `*`   | N |
| focus marker  | U+F0DA         | `▸`     | `>`   | N |
| INTERACT      | U+F11C (kbd)   | `►`     | `>`   | N |
| limit bar     | —              | `▮▯`    | `#-`  | N |
| agent badge   | `C` / `X` letter in `accent`, all sets |

Nerd Font code points are private-use; patched "Mono" variants render them
1 cell, "Propo" variants may not — another reason `nerd` is opt-in. Glyphs
are emitted only through `theme.Icon(name)`; a table test asserts widths.

- **Borders** (three weights, three ascii forms for non-UTF-8 locales):

| Pane state | unicode                      | ascii            |
|------------|------------------------------|------------------|
| inactive   | `┌─┐ │ └─┘` light            | corners `+`, `-` `\|` |
| focused    | `┏━┓ ┃ ┗━┛` heavy, plus the focus marker (`>` / `▸`) on the selected row | corners `#`, `=` `\|` |
| INTERACT   | `╔═╗ ║ ╚═╝` double           | corners `*`, `=` `*` |

- No italics, no underline for meaning. Bold only for emphasis.
- OSC 8 hyperlinks: on the workspace path in the header only, text identical without it.

## 4. Layout

Three columns. Widths are **outer** (including the border), inner = outer − 2.

| Pane     | Outer width           | Inner |
|----------|-----------------------|-------|
| projects | 22                    | 20    |
| sessions (selected project) | 38 (fixed) | 36 |
| output (INTERACT when focused) | remainder, ≥ 40 | ≥ 38 |

Rows: line 1 header, lines 2…H−1 panes (outer height H−2), line H getah bar.

Breakpoints: **≥ 100 columns → three panes**; **< 100 → single-pane stack**
(one pane at a time, breadcrumb in the header, `h`/`l` move through the
stack). Minimum size **80×24**; below that a single centred line:
`bungkus-mcc needs at least 80×24 (now 72×20)`. No other tiers.

## 5. Components (the reusable part)

Future bungkus products **must keep**: the palette and its rules (§2), the
three border weights, the glyph table and its ascii default, the getah bar
anatomy, the state vocabulary (§5.3), the voice (§5.6), the mascot and its
usage rules (§5.7).
They **may vary**: layout, which panes exist, keys beyond the global set,
whether there is a header line.

### 5.1 Getah bar (status bar, always the last line)

`␣MODE␣␣<keys for the focused pane, · separated>` … right-aligned `<global figures>`.

- Mode word first, reverse video: `NORMAL` in `fg-muted`, `INTERACT` in
  `warn`, `FILTER` in `info`.
- Keys are for the **focused pane only**, generated from the keymap.
- Truncation when narrow, from the right: global figures go first, then the
  key hints one by one from the end. Never dropped: the mode word, `? help`,
  and in INTERACT the exit chord.
- Transient messages (errors, "copied") replace the key hints for 5 s.

### 5.2 Card anatomy (sessions pane, inner width 36)

```
┃! C #a3f1 write proposal        12m   gutter · state glyph · agent badge · #id · title · right: elapsed or state word
┃  needs you · permission: Bash        line 2: state word · detail (tool / prompt kind / exit line) [· model when routed]
┃  499k tok · $1.42 · ctx 37%          line 3: compact usage (`-` when unknown)
┃  * research hooks             / 3m   one line per subagent (flat list): glyph · description · state glyph · time
```

- Card order within the pane: by state (needs you, failed, working, your
  turn, stopped, wrapped), then most recent first.
- Gutter column: `┃` in `warn` for needs-you, `err` for failed, space otherwise.
- Title = **the session's name**, as the agent itself knows it (decided):
  Claude's session name (set at launch with `--name`, renamed inside the
  session, or auto-titled — whatever the status line's `session_name` /
  SessionStart's `session_title` says, ARCHITECTURE.md §5.4); Codex has no
  name source mcc may read in stage 1. Fallbacks in order: the name given
  in the `n` picker, the first prompt line, then `untitled`. Sanitised,
  truncated to fit. A rename inside the agent updates the card on the next
  status-line report.
- `#id`: first 4 hex chars of the agent's own session id, in `info`.
- Cards never collapse; when the pane is short, it scrolls (the selected
  card is kept in view). **The selected card is expanded (§6.3) only while

  its `↻` reset times first, then truncates; the `cost` line drops its
  parenthetical first. The card mocks below are inner width 36; the
  expanded mock in §6.3 has the focus marker in column 1, leaving 35.

## 8. Keybindings

Vim motions and arrow keys, everywhere. One file (`internal/tui/keymap.go`,
`bubbles/key.Binding`), grouped per pane and per mode; the help overlay and
getah bar are generated from it. Uniqueness is tested **per pane/mode**, so
`n` can mean "new session" in two panes and nothing elsewhere.

Two modes. **NORMAL** exists only while the projects or sessions pane is
focused. **The output pane has no NORMAL: focusing it is INTERACT** — every
key goes to the agent until the exit chord (§8.5). So `l`/`→`/`tab` from
the sessions pane, `enter` on a session, or a click on the output pane all
start passthrough at once, and the border/banner/mode word/hint change in
the same frame.

### 8.1 Everywhere (NORMAL)

| Keys                                              | Action                                  |
|---------------------------------------------------|-----------------------------------------|
| `h` `l` · `←` `→` · `tab` `shift-tab`             | previous / next pane (moving onto the output pane enters INTERACT) |
| `j` `k` · `↓` `↑`                                 | move / scroll                           |
| `gg` `G` · `home` `end`                           | first / last                            |
| `ctrl-d` `ctrl-u` · `pgdn` `pgup`                 | half page                               |
| `!` · `ctrl-]`                                    | jump to the next needs-you session **across projects**: switches the sidebar selection to that project, selects the card, and enters the output pane (INTERACT) so the answer can be typed at once |
| `z`                                               | zoom the output pane (toggle; stays in the current mode — from INTERACT: `ctrl-\` then `z`) |
| `/`                                               | filter the focused list (FILTER mode: type, `enter` keep, `esc` clear). The list *is* the filter result, so `j`/`k` walk matches; there is no match-next key |
| `w`                                               | workspace screen                        |
| `?`                                               | help                                    |
| `ctrl-l` · `R`                                    | redraw (`R` for tmux + vim-tmux-navigator users, whose `ctrl-l` never arrives) |
| `q` · `ctrl-c`                                    | quit (confirm if anything is running)   |

`gg` is the only two-key sequence (pending `g` shown in the getah bar,
cleared by the next key).

### 8.2 Projects pane

| Keys        | Action                                                        |
|-------------|---------------------------------------------------------------|
| `enter`     | focus the sessions pane of the selected project               |
| `j` `k`     | move the sidebar selection; the sessions pane switches to that project |
| `n`         | new session for the selected project (same picker as below)   |

### 8.3 Sessions pane (selected project)

| Keys                     | Action                                                        |
|--------------------------|---------------------------------------------------------------|

### 8.4 Output pane

There is no NORMAL mode on the output pane (decided). Reading without
typing, stage 1: the **mouse wheel** over the output pane scrolls mcc's
scrollback (`scroll inside the agent` hint when the agent is on the
alternate screen); `z` zooms it from NORMAL (`ctrl-\` then `z` from
INTERACT). Copying text is the terminal's own selection (shift/option
drag, §8.6) — no `y` key.

### 8.5 INTERACT (the output pane, whenever it has focus)

Every key, paste and (if the agent enabled it) mouse event goes to the
agent: `esc`, `tab`, `shift-tab`, arrows, `enter`, `q`, `?`, `ctrl-c`,
`ctrl-d`, every ctrl chord — this is how prompts, slash commands, edit
acceptance and permission answers are typed. Exceptions:

| Keys                 | Action                                                            |
|----------------------|-------------------------------------------------------------------|
| `ctrl-\` (default)   | leave INTERACT: NORMAL with the **sessions pane** focused. Configurable: `interactExit` in config, any single chord (suggested alternate: `ctrl-^`) |
| `ctrl-z`             | swallowed (a suspended agent cannot be resumed from inside a pane)  |
| mouse click on another pane | leaves INTERACT and focuses that pane                       |
| mouse wheel          | scrolls mcc's scrollback unless the agent enabled mouse reporting  |

Accidental passthrough is the main risk of this design. Mitigations: the
double border, the `INTERACT` title, the reverse-video mode word and the
`ctrl-\ back` hint all render in the same frame the pane gets focus; the
sessions-pane hint for `enter`/`l` already says `(ctrl-\ back)`; and when
the session process exits, INTERACT ends by itself (NORMAL, sessions pane).

Why `ctrl-\` by default: a plain C0 byte (0x1C) that arrives even without
the kitty protocol and through tmux without `extended-keys`; not a vim
motion; not bound by Claude Code or Codex (Claude Code documents `ctrl-\`
as reserved, which is why they don't use it). Known clashes, hence the
config key: **vim-tmux-navigator** binds `C-\` (and `C-h/j/k/l`) in tmux;
**VS Code / Cursor** may bind `ctrl+\`; on **JIS** keyboards `\` is the `¥`
key (kitty/iTerm2/Terminal.app send 0x1C for ctrl-¥ — verify in M3); on
**German** layouts `\` needs AltGr. Suggested alternate: `ctrl-^` (`ctrl-]`
is taken by `!`'s twin). `esc` is never the exit: agents use it constantly.
To send a literal exit chord to the agent: not supported in stage 1 (no
agent needs it).

zellij note: zellij's default modes eat `ctrl-g/p/n/t/o/s/h/q` before any
app sees them (`ctrl-g` toggles *lock mode*, which then passes everything
through); `ctrl-\` is not among them.

### 8.6 Mouse

Click focuses a pane / selects a row (and exits INTERACT if the click is
outside the output pane); a click on the output pane focuses it, i.e.
enters INTERACT; wheel scrolls the pane under the pointer. Text selection: with mouse reporting on,
terminals need a modifier to select (kitty/Ghostty/iTerm2 `shift`-drag,
WezTerm/Alacritty `shift`, Terminal.app `option`-drag) — shown in the help
overlay; `--no-mouse` / `mouse: false` turns reporting off entirely.

## 9. Notifications

Setting `notify: "bell" | "desktop" | "off"`, **default `bell`**.

- On the transitions **→ needs you** and **→ failed**: `bell` sends BEL
  (terminals map it to a sound, a badge or a tab highlight); `desktop`
  additionally sends a desktop notification via OSC 9 (iTerm2, WezTerm,
  Ghostty, VS Code), OSC 99 (kitty) or OSC 777 (urxvt-style, foot),
  chosen by `TERM_PROGRAM`/`TERM`; inside tmux/zellij OSC 9 is passed
  through only where the multiplexer allows it — degrade to `bell`.
- Terminal title (OSC 2) always reflects the tally: `bungkus-mcc · 1 needs
  you` / `bungkus-mcc · 2 working` / `bungkus-mcc`. The previous title is
  saved and restored with XTWINOPS push/pop (`CSI 22;0t` on start,
  `CSI 23;0t` on exit); terminals without it simply keep our last title.
- The header tally and getah-bar tally are visible in every mode.

## 12. Accessibility checklist (per screen, at review)

- Every state has glyph + word + colour; screenshots taken with `NO_COLOR=1`.
- Focus visible without colour (border weight + marker); INTERACT visible by
  four signals (border, title, mode word, hint).
- Nothing lives only in the header tally; the sidebar badge repeats it.
- All text tokens ≥ 4.5:1 on the painted backgrounds and, for the fallback
  set, on the reference backgrounds (§2 tables); the fallback `info`

  `background: terminal` renderings attached for theme changes.
